# 故障排查：先判断卡在哪一层

| 现象 | Codex 先检查 | 用户需要做什么 |
|---|---|---|
| 找不到 Python / 打开商店 | 检查 `py` 和真实 Python 路径，避开空的商店别名 | 在 Codex 指引下安装公司允许的 Python |
| 依赖安装失败 | 网络、公司代理、Python 版本和 pip 错误；保留非秘密错误 | 必要时找 IT；不关证书验证、不用来历不明镜像 |
| 双击脚本被公司阻止 | 文件是否完整解压、签名/脚本策略 | 由 IT 放行已审阅脚本；不要永久放开执行策略 |
| TLS/DNS/超时 | 主机拼写、993 可达、公司网络、代理和系统时间 | 确认当前网络；代理/防火墙由 IT 处理 |
| 登录失败 | 完整邮箱地址、IMAP 服务开通、授权码/密码类型、账号/IP 策略 | 自己检查网页版和管理员设置，重新遮蔽输入一次 |
| 凭据不可用 | Windows 身份、是否误在 WSL/容器/另一个账号中运行 | 用日常 Windows 用户重做凭据步骤，不给密码到聊天 |
| CLI 成功，MCP 失败 | Python 绝对路径、配置路径、启动参数、Codex 所在主机/用户 | 重启对应 MCP/本地 Codex；不用全局放开权限 |
| MCP 没有工具 | 配置所在的 CODEX_HOME、项目是否信任、已有同名服务器 | 由 Codex 修改同一处配置，保留其他服务器 |
| 搜索为空 | 查询目录、日期、关键词、分页、跳过字段 | 给一个已知标题或日期作对照；不要立刻重建全库 |
| 中文目录失败 | `mail_list_folders` 是否列出、编码/引用是否正确 | 不手打猜名字，让 Codex 选返回的目录名称 |
| UIDVALIDITY 不一致 | 邮箱目录是否被迁移/重建 | 重新搜索该邮件，使用新结果的标识 |
| 超大邮件被跳过 | 查看 size 与限制，不无限增大读取上限 | 网页版人工阅读或下载需要的单个附件 |
| 附件读不了 | 文件类型、加密、扫描件、截断、读取工具是否可用 | 按具体格式提供本地解密/视觉核对帮助 |

## 原则

同样的诊断失败两次，就换路径定位；连续猜密码可能触发锁定。`system_status` 正常只是程序配置存在，在线检查请用 `doctor` / `mail_list_folders`。

如需反馈到公开 GitHub Issue，只提供系统版本、Python 版本、项目版本、失败阶段和脱敏错误代码。不要上传配置原件、完整终端录屏、邮箱地址、密码、正文、财务附件或凭据管理器画面。

如果命令在普通 Windows 终端成功、在 Codex 的沙箱中失败，应定位运行身份和权限。Windows 原生沙箱可能采用受限身份；凭据属于用户，而不是任意后台账户。优先让本机 MCP 由同一登录用户运行，仅为所需主机和路径授予访问；企业限制交 IT。不能把凭据移到明文文件来绕过。
