# 测试与现场验收

## 自动测试的范围

测试均用虚构邮件和临时目录，不需要真实 263 密码。覆盖只读协议、中文目录/MIME、UIDVALIDITY、附件边界、分页、账号隔离、增量缓存、失败状态、原件哈希和真实 MCP stdio 握手。

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

GitHub Actions 使用 Windows runner 和不同 Python 版本运行离线测试，并检查 PowerShell 脚本语法。Windows 测试可创建并删除仅属于该次测试的随机虚构凭据，验证原生凭据后端。它不连接她的 263 账户，不代替 Windows 11 现场验收，也不能证明她公司的策略允许计划任务。

本机 macOS 测试通过只说明跨平台代码和协议可运行；Windows CI 结果以仓库 Actions 最新提交为准。没有实际运行的项目保持“未测”，不把安装脚本和代码审查当作登录成功。

## 同事电脑必须完成的验收表

由她的 Codex 在本地 `deployment-local.md` 记录日期、项目提交版本和下列结果，不写秘密或原邮件正文。

| 检查 | 做法 | 通过标准 |
|---|---|---|
| 本机环境 | 安装和离线测试 | 无失败；解释器路径与MCP一致 |
| 263 连通 | doctor、folders | TLS登录和真实目录列表成功 |
| 凭据留存 | 关闭终端再 doctor | 同一 Windows 用户下可用，不重新索要到聊天 |
| 小范围同步 | 指定最近30天或更小范围 | 每目录 success；partial 的原因完整记录 |
| 增量行为 | 同范围再刷新 | 没有新邮件时不重新下载原件 |
| 日期/目录 | 选已知中文目录和跨日邮件 | 原件日期、目录、UID 定位一致 |
| 未读不变 | 选网页版未读信，工具读取，再刷新网页 | 仍未读；不靠代码声明代替核对 |
| 本地查询 | 同步后断网查已知邮件 | 命中已有缓存，显示旧同步时间 |
| 新鲜度 | 网页已看到一封新邮件后手动刷新 | Codex 查到并核对标题/时间；不可由测试工具自动发信 |
| 附件 | 取一个获准 PDF/Excel，核对原件 | 哈希、原邮件定位与内容一致，未执行宏/程序 |
| MCP | 实际调用 status、search、get、refresh | 不是仅工具列表出现；结果与CLI一致 |
| 计划任务 | 注册后等待至少一次运行 | 当前用户运行、截止时间推进；仅看到任务存在不算 |
| 重启 | 重启应用，必要时重新登录系统 | MCP与计划任务仍指向正确目录；凭据可用 |
| 停用 | 显示如何禁用/移除该任务和MCP | 用户知道在哪里关掉；无额外后台进程 |

首次覆盖未完成时可以先用已缓存部分，但必须标注范围。超大邮件、文件夹权限不足、扫描附件和未支持格式保持“有缺口”；不能把这些清零以通过验收。

“本机项目位于……；已接入目录……，覆盖自……起，最后成功同步……。普通查询走本地，需要最新时先刷新。自动同步任务……。尚未覆盖……。凭据在 Windows 凭据管理器；停用入口……。”
