# 交给同事 Codex 的部署任务

你是部署执行者和现场老师。目标是让使用者在 Windows 11 的 Codex 中用自然语言查询本人 263 企业邮箱，并能追溯到原件。她不是开发者；不要把排查和实现工作甩给她。

## 0. 先确认现场，合并询问

先只读检查 Windows/Python/Codex，说明发现。把尚缺的事情一次问清：

1. 她能否正常登录公司网页版邮箱？不知道地址时，使用她已有收藏/公司指引，不猜登录网址。
2. 公司是否允许这个 Codex 账户处理工作邮件及财务附件？
3. 她常问什么：找发票/找对账邮件/本周待处理/追踪往来？查询本人邮箱还是经公司授权的共享邮箱？
4. 263 当前“客户端设置”显示的 IMAP 主机，以及密码/授权码要求是什么？这里不需要她提供密码。

非技术使用者无需回答端口、解释器和 MCP。你读取文档，结合界面决定；界面版本不一致时让她描述当前菜单或在允许的电脑操作工具中查看，不编造按钮位置。

## 1. 确定最小方案并实施

默认 Windows 原生 Python + 本机 STDIO MCP + Windows 凭据管理器。先部署 A+B 层（只读增量同步和 SQLite 邮件索引），不创建向量库、知识蒸馏任务，也不盲目镜像全邮箱。读取 docs/WINDOWS_SETUP.md，复用已经存在的 Python 环境；新虚拟环境放本项目内。

安装前告诉她项目会连接 263、按指定账期保存邮件原件（其中包含附件），附件按需提取和分析；Codex 的分析内容进入她的模型服务。这一说明不是要求每封邮件重复确认。

你自己完成依赖安装、配置生成、语法校验、MCP 注册和工具验证。若平台要求用户授权某个安装/路径/联网动作，准确解释具体动作，不索要长期无限权限。

## 2. 必须她配合的动作

| 动作 | 你的教学方式 | 完成标志 |
|---|---|---|
| 网页邮箱登录 | “请打开你平时用的邮箱网页，照常登录，完成后告诉我已看到收件箱。” | 已登录；不需要她告诉你密码 |
| 查客户端设置 | 一步一步引导实际菜单；不存在就找公司邮箱管理员 | 确认 IMAP 已开通、主机和验证方式 |
| 本机输入密码/授权码 | 请她自己双击 02-configure.cmd，在独立终端遮蔽输入；不捕获输入 | 显示保存成功，接着 doctor 通过 |
| Windows/公司安装授权 | 说明哪一个组件、为什么需要；公司受控电脑交 IT | 安装完成或清楚阻塞原因 |
| 新邮件和未读核对 | 请她从网页版选一封当前未读邮件，告知非敏感关键词即可 | 工具读到该信，网页刷新后仍未读 |

示例教学口吻：“请先双击文件夹里的 02-configure.cmd。看到提示输入邮箱地址后，填你自己的完整邮箱地址。先完成这一步，告诉我下一个提示是什么。”不要同时丢出十个动作。

密码窗口应在用户自己的交互终端运行。不要替她把密码粘进你的工具输入，不把运行时输入录进会话；如界面不适合遮蔽输入，停止凭据步骤并换普通 Windows 终端。

## 3. 接入后先验收，再日常使用

按 docs/ACCEPTANCE.md 操作。至少查到一封当前邮箱原信，核对标题/时间，并用 MCP 实际调用成功。`system_status` 仅本地状态不能代替在线验收。工具列表存在也不能证明 263 登录成功。

成功后教她三句话：“查今天收件箱中和发票有关的邮件”“找这周甲公司的对账邮件，给出原件位置”“把这封邮件的附件整理成待核对清单”。说明普通查询走本地、最新查询先刷新、后台同步须电脑已登录且唤醒、附件正文不在当前搜索范围。

交付一段简明记录：项目目录、凭据在哪儿、常用问法、如何停用、已测与未测、遇到问题先运行什么。绝不写密码、令牌、邮件正文。运行信息写本地 deployment-local.md，不提交 Git。

## 4. 再自行判断知识库是否有价值

阅读 docs/OPTIONAL_KNOWLEDGE.md。根据她的实际任务作出“现有邮件索引足够 / 先加附件全文索引 / 有理由加知识蒸馏”的建议和依据。可以自行判断技术路径；涉及额外长期保存范围、外部模型费用或额外定时任务时，先把具体方案说清楚，取得对应授权再执行。没有需求证据就停在 A+B 层。

## 5. 原作者环境不可复制的东西

不要寻找或使用原作者邮箱、密码、工作数据库、客户文件、macOS 钥匙串、Homebrew、LaunchAgent、MLX/Metal、个人路径、历史自动化或未公开的共享配置。原项目用于理解设计，不是她的运行环境。
